## Le problème montré (show the friction, pile-up, implode before the switch)

Le plan 2 : la friction se voit au lieu de se dire. Un objet du problème s'accumule en accélérant (un chiffre, des cartes, des erreurs), puis tout se comprime en un point juste avant la bascule. Chez AIsa, le problème dure 3,7 s et la solution tombe sur le drop (voir *L'arc de pitch : problème → solution → preuves → appel* au chapitre 10).

**Quand l'utiliser** : plan 2 de la timeline type (W : « montrer la friction, pas un paragraphe »), entre l'accroche et la révélation, en promo SaaS et en typo cinétique 1600. Il prépare le temps fort : son état de sortie est le point d'où naît le produit. À éviter sans révélation derrière, ou deux fois dans le même film.

**Règles**

1. **Un objet, pas une phrase** (W). Un objet concret, chiffré ou saturé, pendant 1,5 à 4 s : URL de 164 caractères, 5 000 clés, une centaine de tuiles. Prendre les mots exacts des clients (chapitre 10). Ici, 7 temps, soit 3,3 s.
2. **Le désordre accélère.** Le chiffre monte en ease-in (×1,25 par image environ chez AIsa) et s'arrête sec, sans ralenti. Sa couleur passe du neutre à l'alarme : blanc → #E8513A chez AIsa, navy → #FD504F chez Bento.surf.
3. **Un héros, le reste attend** (F). Le chiffre fait au moins 10 % H (14 % chez AIsa). Les puces sont secondaires : on sent leur nombre, on ne les lit pas. Pas de mur de mots flous (rejeté par l'utilisateur) : puces nettes de 2 à 3 mots, jamais sur le héros.
4. **Compresser avant la bascule.** Contraction en ease-in de 10 à 22 im, finie 1 à 4 im avant le temps ; point final d'environ 1 % H (voir *La compression : en point ou en ligne, puis l'éclosion* au chapitre 4). Tout converge vers le point où naîtra la solution.
5. **Le son monte avec le désordre.** Un coup par mot, sur le temps ; la montée sonore accompagne la contraction. Pour un silence avant le drop, le point tient de 6 im à un temps. Image et son se vident ensemble (voir *Le temps fort* au chapitre 9).
6. **Une seule fois par film.** La compression sert un ou deux temps forts par vidéo ; répétée, elle devient l'accent unique que l'utilisateur rejette (chapitre 4).

**HyperFrames (GSAP)**

```js
// Plan 2 · Problème montré (globale f113-f308) : accumulation, puis compression en point
const FPS = 60, BPM = 128, BEAT = 60 / BPM;
const at = (bar, beat = 0) => ((bar - 1) * 4 + beat) * BEAT;
const F = n => n / FPS;
const T = (bar, beat = 0) => Math.round(at(bar, beat) * FPS) / FPS;
// Hasard à graine (mulberry32) : les mêmes positions à chaque rendu
const rng = (s => () => { s = (s + 0x6D2B79F5) | 0; let t = Math.imul(s ^ (s >>> 15), 1 | s);
  t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t; return ((t ^ (t >>> 14)) >>> 0) / 4294967296; })(1600);
const chips = gsap.utils.toArray(".chip");                  // 24 puces, toutes calculées d'avance
const POS = chips.map(() => ({ x: (rng() - 0.5) * 1600, y: (rng() - 0.5) * 820, r: (rng() - 0.5) * 10 }));
const START = T(2), STOP = T(3, 2), END = T(3, 3) - F(1);    // f113, f281, f308
const n = { v: 1 }, out = document.querySelector("#count");

tl.set(chips, { autoAlpha: 0, x: i => POS[i].x, y: i => POS[i].y, rotation: i => POS[i].r }, 0)
  .set("#dot", { autoAlpha: 0 }, 0)
  // 1. Le chiffre héros accélère jusqu'à la cible et vire à l'alarme (couleur sans rebond)
  .to(n, { v: 5000, duration: STOP - START, ease: "power3.in",
           onUpdate: () => (out.textContent = Math.round(n.v).toLocaleString("en-US")) }, START)
  .to("#count", { color: "#E8513A", duration: STOP - START, ease: "power2.in" }, START);
// 2. Un mot de douleur par temps, le mot neuf seul en accent
["#p1", "#p2", "#p3", "#p4", "#p5"].forEach((sel, k) => {
  tl.fromTo(sel, { autoAlpha: 0 }, { autoAlpha: 1, duration: F(4), immediateRender: false }, T(2, 1 + k))
    .set(sel, { autoAlpha: 0 }, T(2, 2 + k));
});
// 3. Les puces s'empilent, une toutes les 6 im ; 4. Tout se comprime, fini 1 im avant le temps
tl.to(chips, { autoAlpha: 1, duration: F(3), stagger: F(6), ease: "none" }, T(2, 1))
  .to([...chips, "#count", "#pain"], { x: 0, y: 0, scale: 0.02, duration: F(14), ease: "power2.in" }, END - F(14))
  .set([...chips, "#count", "#pain"], { autoAlpha: 0 }, END + F(1))
  .set("#dot", { autoAlpha: 1 }, END + F(1));               // f309 : le point seul, état de sortie
```

**After Effects**

- Chiffre : un calque de texte, Source Text (Texte source) par expression, avec t = linear(time, début, fin, 0, 1) et valeur = Math.round(5000 × t³) (≈ power3.in). Arrêt sec : aucune clé d'arrivée lissée.
- Couleur : Effect › Generate › Fill (Effet › Générer › Remplissage), clés de blanc à #E8513A sur la même plage.
- Puces : une précomposition dupliquée 24 fois (Edit › Duplicate (Édition › Dupliquer), Ctrl+D), puis Animation › Keyframe Assistant › Sequence Layers (Assistant d'image clé › Séquencer les calques) pour un départ toutes les 6 im.
- Compression : tout le plan dans Layer › Pre-compose (Calque › Précomposer). Scale (Échelle) de 100 à 2 % en 14 im ; dans le Speed Graph (graphe de vitesse), influence de sortie de 70 % sur la 1re clé. Activer le Motion Blur (Flou de mouvement).
- Point : calque de forme Ellipse de 11 px au centre, visible dès f309, sur un marqueur de composition.

**Contrôle** : rendre f113, f169, f225, f281, puis une bande de 8 images de f295 à f309 (une toutes les 2 im). À f169 et f225, le chiffre est le seul élément lisible et les puces ne le touchent pas. À f281, la cible est posée, en couleur d'alarme. Sur la bande, la contraction accélère (écarts qui grandissent entre images) et f309 ne montre qu'un point. Vérifier au son que chaque mot tombe sur son coup.
