## La grille de points unitaires (unit chart, dot matrix fill, heatmap fill, dot map)

Une grille où chaque point vaut une unité : une publication, un lieu, un siège. La proportion se voit avant d'être lue : 140 points saumon sur 172 disent 81 % mieux qu'un chiffre seul. Les points servent ensuite d'objets relais : ils s'envolent pour dessiner une carte ou s'empilent en histogramme. À distinguer de la trame décorative (chapitre 6, « La grille générative en onde ») : ici, chaque point compte. Vue dans 21 vidéos, dont 15 notées 4 ou 5.

**Règles de construction**

1. Annoncer l'unité à l'écran : « 140 of 172 publications co-hosted » (palashbagchi11), « um ponto por lugar » (jesscaroline7), « 100 / USERS · 10 × 10 » (sudiyasa), « 19 out of 20 » (henkvaness). 20 à 100 cases pour compter, des centaines pour une masse (172, 395, 1 534).
2. Construire en neutre, puis colorer. La grille gris clair naît en vague : en diagonale depuis un coin en ≈ 13 im à 30 fps (palashbagchi11), du centre en ≈ 20 im (blushpetal795). Ensuite une seule couleur porte la valeur, plus une exception au plus : la 14e case verte (henkvaness), les points noirs à 8,0 s (palashbagchi11).
3. L'ordre de remplissage dit la nature de la donnée. Au hasard pour une part d'une population (palashbagchi11 ; melvynx, 80 % des points deviennent des anneaux). En ordre de lecture pour compter (henkvaness, ≈ 3 im par case ; tak3sh8, 4-5 im par entrée). Par blocs contigus pour des parts (triglyceee, ≈ 4 sièges par image).
4. Le chiffre pilote le remplissage à chaque image : la part colorée suit le compteur (palashbagchi11 ; blushpetal795, front diagonal jusqu'à 500K+ ; ratheejaisal, heatmap avec le revenu). Voir « Le compteur qui roule ».
5. Les unités discrètes tombent sur la grille musicale. Atterrissages sur trois temps consécutifs (thilina, f541, f571, f601 à 120 BPM), dépôts toutes les 15 im, soit au demi-temps (thilina, le bocal). Sudiyasa colore 17 tuiles sur le temps, puis les élève à 1,5 im d'écart.
6. Les points sont des objets relais : même point, nouvelle place. Grille → carte en ≈ 0,8 s (jesscaroline7), pluie → histogramme en 0,9 s (marouanegazouzi), vignettes → points en ≈ 20 im ease-in-out puis une tige toutes les 4 im (miskinho). Voir chapitre 4, « L'objet relais ».

**Verdict** : à reprendre. C'est la façon la plus concrète de montrer une proportion ; ses points sont des relais tout trouvés pour ton match cut « le point devient le point du graphique ». Garde un point = une unité annoncée : sans unité, la grille redevient un décor.

**Quand l'utiliser** : en explainer de données (part, sondage, sièges, effectifs) et en promo SaaS pour la preuve « X sur Y » (comptes, utilisateurs, lieux). Fonction preuve, accroche chiffrée, ou enchaînement quand les points deviennent le graphique suivant. On la choisit au découpage ou aux enchaînements, puis on la construit plan par plan. À éviter pour une valeur seule (« La jauge qui se remplit »), pour comparer des valeurs proches (« Les barres qui poussent et se réordonnent ») et avec des légendes sous 2 % H (adamdesgns : 1,5 % H, illisible).

**HyperFrames (GSAP)**

```js
// 172 points (un par publication) nés en vague depuis le coin,
// puis le pourcentage pilote la part colorée (ordre tiré avec une graine)
const FPS = 30, BPM = 128;
const BEAT = 60 / BPM;
const at = b => Math.round(b * BEAT * FPS) / FPS;      // temps → image exacte
const F = n => n / FPS;
const N = 172, COLS = 15, HIT = 140;                   // 140 sur 172 = 81 %
const box = document.querySelector("#dots");
for (let i = 0; i < N; i++) box.appendChild(Object.assign(document.createElement("i"), { className: "dot" }));
const dots = [...box.children];

// Mélange déterministe (Park-Miller) : le même tirage à chaque rendu
let seed = 7;
const rnd = () => (seed = (seed * 16807) % 2147483647) / 2147483647;
const order = dots.map((_, i) => i);
for (let i = N - 1; i > 0; i--) { const j = Math.floor(rnd() * (i + 1)); [order[i], order[j]] = [order[j], order[i]]; }
const rank = []; order.forEach((d, r) => { rank[d] = r; });

tl.set(dots, { autoAlpha: 0, scale: 0.4, backgroundColor: "#DADADA" }, 0);
tl.to(dots, { autoAlpha: 1, scale: 1, duration: F(4), ease: "power2.out",
  stagger: { grid: [Math.ceil(N / COLS), COLS], from: 0, amount: F(13) } }, at(8));  // vague en 13 im

const p = { k: 0 };                                     // nombre d'unités colorées
tl.to(p, { k: HIT, duration: 3, ease: "power2.inOut",   // 0 → 81 % en 3 s
  onUpdate() {
    const k = Math.round(p.k);
    dots.forEach((d, i) => { d.style.backgroundColor = rank[i] < k ? "#E27C78" : "#DADADA"; });
    document.querySelector("#pct").textContent = Math.round(k / N * 100) + "%";
    document.querySelector("#sub").textContent = `${k} of ${N} publications co-hosted`;
  } }, at(10));
```

**After Effects**

- Un Shape Layer (calque de forme) « point » avec une Ellipse de 14 px, dupliqué 172 fois (Ctrl + D). Sur Position, l'expression `i = index - 2; [1100 + (i % 15) * 22, 220 + Math.floor(i / 15) * 22]` range la grille (index 1 = calque de contrôle).
- Contrôle : un Null Object (objet nul) « CTRL » avec Effect › Expression Controls › Slider Control (Options pour expressions › Paramètre glissière) nommé « Part ». Deux clés, 0 → 81 sur 3 s, avec Easy Ease (Lissage de vitesse, F9).
- Couleur : sur Contents › Ellipse 1 › Fill 1 › Color (Contenu › Ellipse 1 › Fond 1 › Couleur), `seedRandom(index, true); random() * 100 < thisComp.layer("CTRL").effect("Part")("Slider") ? [0.89, 0.49, 0.47, 1] : [0.85, 0.85, 0.85, 1]`. Tirage fixe par point ; part approchée à quelques points près.
- Vague : sur Scale (Échelle), `d = length(transform.position, [1100, 220]); s = ease(time - 3.75 - d / 1500, 0, 4 / 30, 0, 100); [s, s]`. Le chiffre : sur Source Text (Texte source), `Math.round(thisComp.layer("CTRL").effect("Part")("Slider")) + "%"`.
- Envol vers une carte ou un histogramme : un second Slider « Morph » de 0 à 1 sur ≈ 24 im, et sur Position `linear(morph, 0, 1, grille, cible)` (cible : la colonne de l'histogramme ou le lieu). Un calque par point, pour que l'œil le suive.
