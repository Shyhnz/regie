## L'arc de pitch : problème → solution → preuves → appel (problem-solution-proof-CTA arc, launch narrative)

L'ordre argumentatif d'une promo, en 5 à 7 parties : un problème concret et chiffré, une solution qui naît de l'objet du problème, des preuves, puis la marque et l'appel à l'action. Dans la seule vidéo notée 5/5 de la famille, les preuves occupent 55 % des 15 s et chaque partie sort de la précédente. Transposé à la lettre, le même ordre devient une suite de diapositives. Vue dans 49 vidéos, dont 37 notées 4 ou 5.

**Découpage type (15 s à 120 BPM = 30 temps)**

Problème : 3 temps (1,5 s). Solution : 1 temps, fini par un clic sur le drop. Preuves : 17 temps (8,5 s, environ 55 %). Rafale ou récap : 4 temps (2 s). Signature : 5 temps (2,5 s), dont 1,6 s de tenue au plus. Ce sont les proportions de la vidéo 5/5 (steventey, étude 60 fps).

Le guide Otom propose 4 plans pour 15 s : question 3 s, problème 3 s, solution 5 s, appel 4 s (guide Otom, p. 10). Nos mesures placent la bascule plus tôt (1,5 s chez steventey, 5,6 s chez 0xfemyn), et donnent plus aux preuves qu'au carton final. La Bible retient ses mesures.

**Règles de construction**

1. Montrer le problème, pas le dire : un objet concret, chiffré ou saturé, en 1,5 à 4 s. URL de 164 caractères (steventey), 5 000 clés (0xfemyn), une centaine de tuiles (gabrielbuzziv). Prendre les mots exacts des clients pour le désordre (guide Otom, p. 13).
2. La solution naît de l'objet du problème, sur le temps fort. Compression power2.in en 10 im, éclair d'1 im, ressort 15 + 12 im (steventey, étude 60 fps). Bascule sur le drop chez 0xfemyn et reyzostyle (« Stop guessing. »).
3. Les preuves pèsent le plus, environ la moitié du film. Chaque preuve = un titre de 2 à 5 mots + un visuel chiffré (ceowinkz ; cansincengiz, 4 preuves de 1,2 à 1,4 s). Compteurs en power3.out sur 33 à 140 im (steventey). Gains réels et vérifiables seulement (guide Otom, p. 12).
4. Chaque partie dure un nombre entier de mesures, et les dernières raccourcissent. Exemples : 7 blocs d'une mesure (astrodevil), 1-2-2-1-1-1 mesures (thayto-dev), 8 fonctions en 2 s avant le logo (steventey). Des parties égales sans montée font un diaporama (alex-prompter, amitsingha89, notés 2).
5. Boucler : le slogan reprend l'accroche, l'appel est concret. « Every missed call is a missed client. » devient « Never miss a call again. Or a client. » (fractadev). Puis URL ou bouton : voir la signature finale.

**Verdict** : à reprendre. C'est la structure qui vend en 15 s, à condition que chaque partie sorte de l'objet de la précédente. C'est ton « chaque plan est fait du précédent » appliqué au récit entier.

**Quand l'utiliser** : promo SaaS, lancement de produit, publicité de 10 à 30 s, explainer commercial avec voix. C'est l'ossature du film, de l'accroche à la signature. On la fixe à l'étape « message et script » (une phrase par partie), puis on la pose sur la grille au découpage. À éviter pour un showreel ou une pièce d'ambiance (préférer le chapitrage), et sans preuve réelle à montrer.

**HyperFrames (GSAP)**

```js
// Arc de pitch sur 15 s à 120 BPM, et bascule problème → solution sur le drop
const FPS = 60;
const BEAT = 60 / 120;                        // 1 temps = 30 im, 1 mesure = 2 s
const at = b => b * BEAT;
const F = n => n / FPS;
const H = 1080;                               // hauteur de la composition
// Découpage en temps : problème 3, solution 1, preuves 17, rafale 4, signature 5 (= 30)
const PARTS = [["#problem", 0], ["#solution", 3], ["#proofs", 4], ["#burst", 21], ["#endcard", 25]];
tl.set(PARTS.map(p => p[0]), { autoAlpha: 0 }, 0);
PARTS.forEach(([sel, b], i) => {
  tl.set(sel, { autoAlpha: 1 }, at(b));
  if (i < PARTS.length - 1) tl.set(sel, { autoAlpha: 0 }, at(PARTS[i + 1][1]));
});
// Bascule (mesures de l'étude 60 fps, ramenées sur la grille)
const DROP = at(4);                           // 2,0 s : le clic tombe sur le drop
tl.set("#pill", { scale: 0 }, 0)
  .to("#url", { scaleX: 0.087, filter: "blur(6px)", duration: F(10), ease: "power2.in" }, at(3) - F(10))
  .set("#flash", { autoAlpha: 0.31 }, at(3) + F(1))              // éclair d'1 image
  .to("#flash", { autoAlpha: 0, duration: F(11), ease: "power1.out" }, at(3) + F(1))
  .to("#pill", { scale: 1.18, duration: F(15), ease: "sine.out" }, at(3) + F(2)) // ressort
  .to("#pill", { scale: 1, duration: F(12), ease: "sine.inOut" }, at(3) + F(17))
  .set("#cursor", { x: 0.33 * H, y: 0.36 * H }, 0)
  .to("#cursor", { x: 0, y: 0, duration: F(12), ease: "power3.out" }, DROP - F(13))
  .set("#halo", { autoAlpha: 1, scale: 0.1 }, DROP)
  .to("#halo", { autoAlpha: 0, scale: 12, duration: F(15), ease: "power2.out" }, DROP);
```

**After Effects**

- Poser un marqueur de composition aux temps 0, 3, 4, 21 et 25 (1 temps = 30 im à 120 BPM). Nommer chacun dans son champ Comment (Commentaire) : PROBLÈME, SOLUTION, PREUVES, RAFALE, SIGNATURE.
- Une précomposition par partie : Layer › Pre-compose (Calque › Précomposer), point d'entrée sur son marqueur.
- Compression : Scale (Échelle) en X de 100 à 9 % en 10 im. En même temps, Effect › Blur & Sharpen › Gaussian Blur (Flou et netteté › Flou gaussien) de 0 à 6. Speed Graph (éditeur de graphe de vitesse) : influence sortante 70 % sur la 1re clé (≈ power2.in).
- Éclair : un Solid (Solide) blanc à Opacity (Opacité) 31 % sur 1 image, puis 0 % en 11 im. Pastille : Scale 0 → 118 % en 15 im, puis 100 % en 12 im, en Easy Ease (Lissage de vitesse, touche F9).
- Le curseur se pose en 12 im ; le halo du clic part sur le marqueur du drop. Les compteurs de preuve : Effect › Text › Numbers (Texte › Nombres), clé d'arrivée à influence 85 % (≈ power3.out).
